# AI 智能体创新应用大赛参赛准备

> 本文用于项目完善和赛前核验。团队已与老师沟通并获准参赛，队员已开展测试。具体校内使用场景、测试用例与结果应按实际记录补全，不以未核实内容代替证据。

## 作品暂定名称

小暖：语音就医信息整理助手

## 解决的问题

面向不便打字的就诊者及协助其就医的家属，语音整理就诊前信息，并将就诊后转述的医嘱归纳成便于核对的记录，减少口头信息遗漏和重复整理。

**校内场景：**团队已与老师沟通并获准参赛。参赛说明应继续写清实际目标用户、使用环节及老师确认的场景依据；不要把“获准参赛”表述成已在校内业务系统落地。

## 核心流程

1. 用户选择“就诊前准备”或“就诊后整理”。
2. 用户用语音描述情况，系统将语音转写后交给对话模型。
3. 诊前模式只整理已说出的不适、持续时间、既往情况、当前用药、想问医生的问题及待补充信息；不输出诊断或治疗建议。
4. 诊后模式整理用户转述的医嘱、注意事项和复诊安排；剂量等不明确的内容应由用户核对。
5. 用户核对结构化卡片，并可在记忆面板编辑或删除已保存的个人记录。

## 技术路线

- React 移动端界面与 Android WebView 外壳。
- EdgeOne LangGraph 服务处理对话与结构化信息提取。
- ASR/TTS 与大模型通过服务端配置的 API 调用；密钥不应放在前端。
- KV 保存账户会话、档案、用药记录、摘要卡片和最近对话。

近期体验改进：登录/注册页补回小暖标志；激活页面后首次播放简短功能介绍，之后每次进入播放欢迎词。语音交互先显示“正在听清”，识别文字返回后才显示思考状态；自动收音结束等待略微缩短，并可在较长回复的逗号停顿处提前开始播报。上述前端调整尚待真机计时和识别复测，不能当作服务端 ASR 准确率或模型生成速度已达标的证据。

## 已知边界与风险

- 结构化内容由模型提取，可能遗漏或误读；所有卡片须由用户核对后使用。
- 当前记录的服药时间不会触发手机定时通知，不应宣传为主动提醒服务。
- 目前尚未验证校内业务接入、真实用户效果、数据保留周期与部署平台的隐私合规性。
- 不用于诊断、处方、药物推荐或急救判断；紧急症状应联系急救服务。
- 参赛前需确认代码、插图、音色、模型和第三方依赖的授权与来源。

| 时间 | 展示内容 |
|---|---|
| 0:00–0:35 | 说明目标用户、已验证的实际痛点及现有流程问题 |

| 4:00–4:35 | 展示真实测试记录、成功率和未解决问题 |
